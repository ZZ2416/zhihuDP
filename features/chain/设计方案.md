# 设计方案：AI 生成产业链流程图（可交互）

> 版本：v0.1 · 日期：2026-08-22 · 分支：`feature/chain`
> 参考：`DayuanJiang/next-ai-draw-io`（AI 集成 draw.io 生成图表，35k star）——借鉴「AI 经自然语言生成结构化图表数据」思路；前端用**轻量原生 SVG** 实现交互（不引入 mxGraph 重依赖，保持零构建）
> 决策（用户确认）：**左右三列**流程图 · 点击节点看**同类型厂商列表 + 可跳查**

---

## 1. 目标

搜索股票后，详情页新增「**产业链图谱**」卡片：AI 根据股票生成产业链（上游→中游→下游三列节点 + 连线），前端渲染为可交互 SVG 流程图——点击节点展开该环节的**同类型厂商**列表，点击厂商可搜索查看其基本面。

## 2. 数据流

```
POST /api/chain {code, market}（计配额）
  → 服务端 resolve 股票 → LLM 生成产业链 JSON（节点/边/每环节厂商）
  → 服务端校验厂商代码（stock.Resolve，无效过滤/标注）
  → 200 返回 {industry, nodes[], edges[], companies{}}
前端渲染：三列 SVG 图 + 节点交互
```

## 3. AI 生成（prompt → 结构化 JSON）

### 3.1 prompt 约束
```
你是产业研究助手。基于股票「{name}({code})」生成其所在产业链的结构化数据，输出严格 JSON：
{
  "industry": "产业链名称（如 白酒产业链）",
  "nodes": [{"id":"n1","name":"环节名（如 上游-粮食/包装）","stage":"上游|中游|下游","desc":"环节说明（≤20字）"}],
  "edges": [{"from":"n1","to":"n2"}],      // 环节间上下游关系（沿 上游→中游→下游）
  "companies": {"n1":[{"code":"600519","name":"贵州茅台"}], ...}  // 每个环节 3-6 家同类型代表厂商（真实 A 股代码）
}
要求：环节 6-10 个；厂商必须是真实存在的 A 股公司（代码+名称准确）；只输出 JSON，无其他文字。
```

### 3.2 服务端校验
- `stock.Resolve` 校验每个厂商代码（存在性）；无效代码移除；全部无效 → 该节点标注「厂商待补充」
- 校验失败不阻塞（厂商列表尽力而为，标注「AI 生成仅供参考」）

## 4. 数据契约

```go
type ChainNode struct {
    ID    string `json:"id"`
    Name  string `json:"name"`
    Stage string `json:"stage"` // 上游/中游/下游
    Desc  string `json:"desc"`
}
type ChainEdge struct { From, To string }
type ChainCompany struct { Code, Name string }
type ChainResult struct {
    Industry  string                   `json:"industry"`
    Nodes     []ChainNode              `json:"nodes"`
    Edges     []ChainEdge              `json:"edges"`
    Companies map[string][]ChainCompany `json:"companies"` // nodeID → 厂商
    Degraded  bool                     `json:"degraded"`
    ErrMsg    string                   `json:"err_msg,omitempty"`
}
```

## 5. 前端流程图（轻量 SVG，三列）

- 布局：`上游 | 中游 | 下游` 三列；列内节点垂直排列，按 `edges` 连线（SVG polyline + 箭头）
- 节点卡片：名称 + 环节说明（圆角矩形，hover 高亮）
- **交互**：
  - 点击节点 → 右侧/下方展开该环节「同类型厂商」面板：`代码 名称` 列表（带「查看」按钮）
  - 点击厂商「查看」→ 填入搜索框并 `doSearch()`（跳查其基本面/情绪）
  - 节点数多时横向滚动；支持缩放（简单 +/- 按钮）
- 样式复用 `.card`/主题变量；「AI 生成 · 仅供参考」标注

## 6. API 设计

### POST /api/chain（计配额）
- body `{code, market}`；返回 `ChainResult`（非流式，AI 生成一次）
- 失败 502（LLM 或校验失败）；LLM 输出非法 JSON → 重试一次，仍失败 → 400「产业链生成失败」

## 7. 合规

- 产业链图谱为行业结构信息展示，不荐股；「AI 生成仅供参考，厂商信息可能存在误差」标注
- 厂商跳查走既有搜索（基本面/情绪合规链路）

## 8. 架构改动

```
internal/agent/chain.go（新增）：LLM 生成产业链 JSON（prompt + 严格 JSON 解析，复用模型/合规）
internal/server/handler_chain.go（新增）：POST /api/chain
internal/server/server.go：ChainProvider 接口 + 路由 + New 参数
internal/types/types.go：ChainNode/ChainEdge/ChainCompany/ChainResult
cmd/server/main.go：组装 chainProvider（agent + stock.Resolve 校验）
web/index.html + web/js/chain.js + css：产业链卡片 + SVG 渲染 + 节点交互
```

## 9. 验证方案

1. 单测：chain JSON 解析（非法 JSON 重试）、厂商代码校验（有效/无效过滤）
2. 接口冒烟：`/api/chain` 返回真实产业链（茅台 → 白酒产业链：上游粮食/包装/中游酒企/下游渠道，厂商可 Resolve）
3. 前端：三列渲染、节点点击展开厂商、厂商跳查
4. 合规：无荐股；标注 AI 生成
5. 回归：基本面/情绪/对话不受影响；build/vet/test

## 10. 风险与开放问题

1. **AI 厂商准确性**：LLM 可能编造代码——服务端 Resolve 校验过滤 + 「AI 生成仅供参考」标注（诚实降级）
2. **LLM 输出格式**：严格 JSON 约束 + 失败重试 1 次；仍失败返回错误
3. **图复杂度**：6-10 节点三列布局可控；节点过多自动收缩（desc 截断/横向滚动）
4. **draw.io 借鉴度**：不引入 mxGraph（重依赖），用轻量 SVG 实现核心交互（三列 + 点节点）；若后续需完整编辑能力再评估 draw.io 集成
