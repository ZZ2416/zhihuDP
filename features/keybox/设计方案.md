# 设计方案：开屏密钥配置（KeyBox）

- 分支：`ui_premiu`
- 状态：已实现，待评审
- 关联需求：进入 URL 时开屏动画；弹窗配置用户自己的 DeepSeek / 知乎密钥，可跳过用默认；默认密钥公私钥加密防他人利用。

## 一、需求拆解

| 需求 | 方案 |
| --- | --- |
| banner 图（fc3e98）改回 | 不再作为顶栏背景，改为**开屏动画**主视觉（`/pic/kanshan-header.jpg`），顶栏恢复纯主题色 + 毛玻璃 |
| 开屏动画 | 页面加载即全屏展示 banner 图（缩放/淡入，2s），随后淡出移除 |
| 配置弹窗 | 开屏结束弹出「密钥配置」：DeepSeek API Key + 知乎 Access Secret 两个输入框 + 「跳过」/「保存」 |
| 跳过 → 默认密钥 | 默认密钥只存在**服务端 config.yaml**（chmod 600），从不以明文下发到浏览器 |
| 默认密钥防他人利用 | **RSA 公私钥机制**：服务端启动生成 2048 位密钥对，公钥经 `GET /api/config/pubkey` 下发；用户填写的密钥在浏览器内用公钥加密（RSA-OAEP/SHA-256，Web Crypto），`POST /api/config/keys` 提交，仅服务端私钥可解密并热更新到运行配置 |

## 二、密钥安全设计（威胁模型）

```
用户浏览器                         服务端（本机）
─────────────────                 ─────────────────────────
填写密钥明文（不进网络）             config.yaml 默认密钥（仅服务端）
        │                                │
        │ GET /api/config/pubkey  ←──────┤ 返回 PEM 公钥（公开无害）
        ▼                                │
Web Crypto RSA-OAEP/SHA-256 加密 ────────┤
        │ POST /api/config/keys          │ 私钥解密（内存中，不落日志）
        └─────────────────────────────────▼
                          cfg.DeepSeek.APIKey / zhClient 热更新，立即生效
```

- 私钥：进程内存，**每次启动随机生成**，不持久化 → 重启后旧公钥失效，天然防重放。
- 默认密钥：不下发、不回流前端；前端只收到「使用中」的结果（toast）。
- 传输：用户密钥仅在浏览器内加密后过网络，密文 base64；明文不落日志、不入 SSE。
- 局限（如实说明）：本方案防**网络窃听/前端泄露/日志泄露**；本机磁盘上的 config.yaml 明文默认密钥属于部署者自有资产（600 权限 + gitignore），不在 Web 威胁面内。
- 热更新链路：`agent.Deps.DeepSeek` 由值捕获改为 **getter**（每次调用读最新配置），`zhihu.Client` 增加 `UpdateKeys` + 读写锁，弹窗保存后无需重启即刻生效。

## 三、接口设计

### 1. `GET /api/config/pubkey`
- 响应：`{"public_key": "<PEM 公钥>"}`（2048 位 RSA，SPKI PEM）

### 2. `POST /api/config/keys`
- 请求：`{"deepseek_key_enc": "<b64(RSA-OAEP 密文)>", "zhihu_secret_enc": "<b64 或空>"}`
- 字段为空 = 该项跳过（保留原密钥）
- 成功：`200 {"ok":true}`；密文非法：`400 {"error":"..."}`

## 四、前端交互时序

1. `load` → 显示开屏（banner 图动画 2s → 淡出 0.65s → 移除节点）
2. 若 localStorage 无 `zhihudp-keys`（首次）→ 弹配置窗
3. 「跳过」→ 写 `zhihudp-keys=skip`，关窗，toast「已使用内置默认密钥」
4. 「保存」→ 拉公钥 → 对非空字段逐项加密 → POST → 成功写 `zhihudp-keys=custom` + toast；失败展示错误，可重试（不写标记，下次仍弹）
5. 后续访问：不再弹窗（localStorage 已标记）；开屏每次保留（短动画）

# v2 追加：持久密钥加密存储（密文入库，私钥本地）

> 决策（2026-08-16 用户确认）：① 开屏上传无需口令（本机场景）② CLI 生成密钥对 ③ 保留现有「访问者填自己密钥」弹窗

## 目标

部署者本地生成**持久 RSA 密钥对**：公钥加密真实 API 密钥 → **密文入库**（config.yaml），代码/仓库/配置**绝无明文**；私钥文件仅存部署者本地（chmod 600）。访问者只能请求服务器接口使用密钥，全程看不到明文。即使仓库/配置泄露，别人拿到的只是解不开的密文。

## 密钥生命周期

```
部署者本机:  zhihudp keygen
  ├─ 生成 RSA-2048 密钥对
  ├─ 私钥 → ~/.zhihudp/zhihudp_private.pem（600）
  ├─ 公钥 → 派生
  └─ 交互输入 DeepSeek/知乎密钥 → 公钥加密 → 输出两段 base64 密文
部署者:      粘贴密文到 config.yaml（deepseek.api_key_enc / zhihu.access_secret_enc）
服务器启动:  keybox.New(私钥路径) → 读私钥 → 解密密文 → 内存使用（明文不出进程）
访问者:      请求 /api/ask、/api/chat → 服务器内部用密钥调外部 API
开屏上传:    访问者填自己的密钥 → 浏览器用持久公钥加密（Web Crypto）→ POST /api/config/keys
             → 私钥解密 → 热更新 + 密文持久化回 config.yaml（重启仍生效）
```

## 配置新增（config.yaml / config.example.yaml）

```yaml
keybox:
  private_key: "~/.zhihudp/zhihudp_private.pem"   # 私钥路径（部署者本地）
deepseek:
  api_key_enc: "base64密文"     # 与 api_key 二选一；enc 存在时优先（解密覆盖）
zhihu:
  access_secret_enc: "base64密文"
```

## CLI 子命令（cmd/server）

| 命令 | 作用 |
|---|---|
| `zhihudp keygen` | 生成密钥对（私钥存本地）+ 交互输入两个密钥 → 输出密文与写入提示 |
| `zhihudp enc -key sk-xxx` | 用公钥加密单个密钥，输出 base64 密文 |
| `zhihudp pubkey` | 打印公钥 PEM（手动加密用） |

## 接口与热更新

- `GET /api/config/pubkey` → 返回**持久**公钥（替代每次启动随机的临时公钥）
- `POST /api/config/keys` → 私钥解密 → 热更新内存 → **密文原样写回 config.yaml 的 enc 字段**（不写明文），重启后加载解密恢复
- 现有开屏弹窗前端逻辑不变（Web Crypto RSA-OAEP），仅后端密钥对持久化 + 落盘

## 安全说明（如实）

- 密文可安全入库/入仓库；私钥（600 权限）是唯一解密钥匙，在部署者本机
- 服务器需能读私钥文件（本机部署即满足）；若将来部署到远程服务器，私钥需随部署者提供（如挂载卷），文档届时更新
- 「谁都能传」仅适用于本机/可信环境；对外部署时应加管理口令（预留）
