# 设计方案：恢复知乎情绪分析（与基本面分析并存）

> 版本：v0.1 · 日期：2026-08-19 · 分支：`feature/emotion`
> 决策（用户确认）：情绪与基本面**各自独立解读**（两次 LLM）· 知乎密钥**配置+弹窗都恢复** · 情绪面板在**基本面卡之上**

---

## 1. 目标与背景

在基本面分析（四维评分）基础上，**恢复知乎情绪分析**并与之并存：情绪面板（热度/多空占比/参考强度/代表观点）+ 独立 AI 情绪解读。恢复此前删除的知乎数据源（zhihu_search）、sentiment 包、情绪面板 UI。

## 2. 数据源（此前实测，恢复即可用）

| 项 | 说明 |
|---|---|
| 知乎开放平台 | `POST /api/v1/content/zhihu_search`，Bearer 鉴权（access_secret），`GET /api/v1/knowledge/bases` 知识库 |
| 配置 | `config.zhihu.access_secret`（明文或 enc 密文）+ 密钥弹窗知乎字段（RSA-OAEP，复用 keybox） |
| 恢复代码 | `internal/zhihu`（客户端）、`internal/sentiment`（情绪分析：LLM 分类 + 强度分）——从 git 历史（7722088 删除点）恢复并适配当前接口 |

## 3. 功能需求

| # | 需求 | 优先级 |
|---|---|---|
| FR-E1 | 恢复 `internal/zhihu`（zhihu_search 搜索）+ `internal/sentiment`（情绪分析） | P0 |
| FR-E2 | `/api/ask` 事件协议：`stock` → **`sentiment`**（情绪数据）→ `fundamental`（评分）→ `delta`×N（基本面解读）→ `done` | P0 |
| FR-E3 | **独立情绪解读**：`POST /api/emotion/analyze`（SSE 流式，情绪解读，计配额）——前端收到 sentiment 数据后自动触发 | P0 |
| FR-E4 | 前端恢复**情绪面板卡**（基本面卡上方）：热度/多空占比/参考强度(1-10)/代表观点 + 情绪解读区 | P0 |
| FR-E5 | 密钥：`config.zhihu.access_secret`（明文/enc）+ 开屏弹窗加回知乎字段（RSA 加密持久化） | P0 |
| FR-E6 | 合规：情绪面板"参考强度"1-10（非概率）、不荐股；情绪解读过 compliance 过滤 | P0 |

## 4. 数据契约（情绪）

```go
// 复用历史类型（恢复）：
// SentimentResult{Code, Name, Heat, Sample, Ratio{Bull,Bear,Neutral}, Score *int, Items []ViewItem, Degraded, ErrMsg}
```

- 情绪事件 `sentiment`：完整 SentimentResult JSON（前端渲染面板 + 触发解读）
- `POST /api/emotion/analyze` body `{code, market}`：SSE `delta`×N → `done`/`error`（情绪解读，独立于基本面解读）

## 5. AI 解读（各自独立）

- **基本面解读**（现状）：ask 的 delta——四维评分 + 财报 + 估值
- **情绪解读**（新增 /api/emotion/analyze）：注入情绪数据（热度/多空/代表观点）→ 输出 3 段：情绪面总结 / 值得关注的讨论点 / 风险提示（原一期情绪解读 prompt 恢复）
- 两次独立 LLM 调用，互不干扰；都过 compliance 过滤 + 免责

## 6. 架构改动

```
恢复：internal/zhihu（zhihu_search）、internal/sentiment、config.zhihu、handler 情绪事件、前端情绪面板

改造：agent（加 analyze_sentiment 工具，发 sentiment 事件）、chat（上下文加情绪）、keys.js/弹窗（知乎字段）
```

- 情绪解读实现：复用 agent 的模型/合规链路（与 finance.go 同模式），prompt 独立

## 8. 验证方案

1. 单测：zhihu_search 解析、sentiment 分类（降级路径）、emotion/analyze handler
2. 接口冒烟：ask 事件含 sentiment+fundamental；emotion/analyze SSE 流式；知乎密钥生效（真实数据）
3. 合规：情绪解读无买入/概率词；参考强度 1-10
4. 回归：基本面分析、看山对话、密钥弹窗（含知乎字段）正常
5. 全量 build/vet/test

## 9. 风险与开放问题

1. **知乎接口稳定性**：zhihu_search 可能限流/变动——降级策略保留（面板"暂不可用+重试"）
2. **两次 LLM 调用成本**：ask（基本面）+ emotion/analyze（情绪）各一次——配额 20 次/页含 emotion/analyze
3. **AI 解读是否综合**：用户已确认各自独立（不合并）
4. **弹窗密钥**：恢复知乎字段后，弹窗两字段（DeepSeek + 知乎）都走 RSA-OAEP + 密文持久化
